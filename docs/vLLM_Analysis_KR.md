## 1. 프로젝트 개요

### vLLM이란?

vLLM은 UC Berkeley의 Sky Computing Lab에서 개발된 **고성능 LLM 추론 및 서빙 라이브러리**입니다. 현재는 학계와 산업계의 기여를 받는 커뮤니티 주도 프로젝트로 발전했습니다.

### 핵심 가치

| 특성 | 설명 |
|------|------|
| **Easy** | HuggingFace 모델과 원활한 통합, OpenAI 호환 API |
| **Fast** | PagedAttention으로 최대 24배 처리량 향상 |
| **Cheap** | 효율적인 메모리 관리로 비용 절감 |

### 라이선스

Apache 2.0 (오픈소스)

## 2. 핵심 아키텍처

### 2.1 PagedAttention (핵심 혁신)

```
┌─────────────────────────────────────────────────────────────┐
│                    PagedAttention 개념도                      │
├─────────────────────────────────────────────────────────────┤
│                                                             │
│   기존 방식 (연속 메모리 할당)                                  │
│   ┌──────────────────────────────────────┐                  │
│   │  Request 1  │  낭비  │  Request 2    │  낭비  │          │
│   └──────────────────────────────────────┘                  │
│                                                             │
│   PagedAttention (페이지 단위 할당)                            │
│   ┌────┬────┬────┬────┬────┬────┬────┬────┐                │
│   │ R1 │ R2 │ R1 │ R3 │ R2 │ R1 │ R3 │ R2 │                │
│   └────┴────┴────┴────┴────┴────┴────┴────┘                │
│   → 메모리 단편화 해소, 효율성 극대화                           │
│                                                             │
└─────────────────────────────────────────────────────────────┘
```

**효과:**
- KV 캐시 메모리 효율성 대폭 향상
- 동적 메모리 할당으로 다양한 시퀀스 길이 지원
- 2-4배 처리량 향상

### 2.2 Continuous Batching (연속 배칭)

```
┌─────────────────────────────────────────────────────────────┐
│                   Continuous Batching 흐름                   │
├─────────────────────────────────────────────────────────────┤
│                                                             │
│   정적 배칭 (기존)                                            │
│   ├── Batch 1 ──────────┤ 대기 ├── Batch 2 ──────────┤      │
│   │ Req1, Req2, Req3    │      │ Req4, Req5, Req6    │      │
│                                                             │
│   연속 배칭 (vLLM)                                           │
│   ├──┬──┬──┬──┬──┬──┬──┬──┬──┬──┬──┬──┤                    │
│   │R1│R2│R3│R4│R2│R3│R5│R3│R5│R6│R5│R6│                    │
│   └──┴──┴──┴──┴──┴──┴──┴──┴──┴──┴──┴──┘                    │
│   → 요청이 완료되면 즉시 새 요청 투입                           │
│                                                             │
└─────────────────────────────────────────────────────────────┘
```

**효과:**
- GPU 활용률 극대화
- 대기 시간 최소화
- 처리량 극대화

## 3. 주요 기능 및 특징

### 3.1 성능 최적화

| 기능 | 설명 | 효과 |
|------|------|------|
| **PagedAttention** | 페이지 단위 KV 캐시 관리 | 메모리 효율 2-4배 향상 |
| **Continuous Batching** | 동적 요청 배칭 | GPU 활용률 극대화 |
| **CUDA/HIP Graph** | 그래프 기반 실행 | 커널 실행 오버헤드 감소 |
| **FlashAttention** | 최적화된 어텐션 커널 | 어텐션 연산 가속 |
| **Speculative Decoding** | 투기적 디코딩 | 생성 속도 2-3배 향상 |
| **Chunked Prefill** | 청크 단위 프리필 | 프리필/디코드 오버랩 |

### 3.2 양자화 지원

```

├─────────────┼───────────────┼─────────────────────────────┤
```

### 3.3 분산 추론

```
┌─────────────────────────────────────────────────────────────┐
│                    분산 처리 전략                            │
├─────────────────────────────────────────────────────────────┤
│                                                             │
│  Tensor Parallelism (TP)                                    │
│  ┌─────────────────────────────────────────┐               │
│  │ GPU0: Layer 파라미터의 1/4              │               │
│  │ GPU1: Layer 파라미터의 1/4              │               │
│  │ GPU2: Layer 파라미터의 1/4              │               │
│  │ GPU3: Layer 파라미터의 1/4              │               │
│  └─────────────────────────────────────────┘               │
│  → 단일 레이어를 여러 GPU에 분산                             │
│                                                             │
│  Pipeline Parallelism (PP)                                  │
│  ┌─────────┐ ┌─────────┐ ┌─────────┐ ┌─────────┐          │
│  │ GPU0    │→│ GPU1    │→│ GPU2    │→│ GPU3    │          │
│  │ L1-L8   │ │ L9-L16  │ │ L17-L24 │ │ L25-L32 │          │
│  └─────────┘ └─────────┘ └─────────┘ └─────────┘          │
│  → 레이어를 순차적으로 여러 GPU에 분산                        │
│                                                             │
│  Expert Parallelism (EP) - MoE 모델용                       │
│  ┌─────────────────────────────────────────┐               │
│  │ GPU0: Expert 0-15                       │               │
│  │ GPU1: Expert 16-31                      │               │
│  │ GPU2: Expert 32-47                      │               │
│  │ GPU3: Expert 48-63                      │               │
│  └─────────────────────────────────────────┘               │
│  → MoE Expert를 여러 GPU에 분산                             │
│                                                             │
└─────────────────────────────────────────────────────────────┘
```

### 3.4 고급 기능

| 기능 | 설명 |

| **Multimodal** | 이미지, 비디오, 오디오 입력 지원 |

### 7.2 핵심 차이점 비교표

| 항목 | vLLM | llama.cpp / Ollama / LM Studio |
|------|------|-------------------------------|
| **설계 철학** | 고처리량, 다중 사용자 서빙 | 단일 스트림 효율성, 이식성 |
| **언어** | Python (PyTorch 기반) | C/C++ (의존성 최소화) |
| **주요 혁신** | PagedAttention | GGUF 포맷, 메모리 맵핑 |
| **모델 포맷** | HuggingFace 표준 | GGUF (llama.cpp 전용) |
| **GPU 요구사항** | NVIDIA GPU 권장 (CUDA) | CPU만으로도 실행 가능 |
| **Multi-GPU** | 탁월 (TP, PP, EP) | 제한적 |
| **양자화** | GPTQ, AWQ, FP8 등 | 2-bit ~ 8-bit (GGUF) |
| **메모리 사용** | VRAM 90% 사전 할당 | 필요한 만큼만 사용 |
| **시작 시간** | 느림 (모델 로딩) | 빠름 (메모리 맵핑) |
| **모델 전환** | 서버 재시작 필요 | 빠른 전환 가능 |

### 7.5 장단점 요약

#### vLLM

**장점:**
- 동시 다중 요청 처리 시 최고의 처리량
- 강력한 Multi-GPU 지원 (Tensor/Pipeline/Expert Parallelism)
- PagedAttention으로 메모리 효율 극대화
- OpenAI 호환 API로 쉬운 마이그레이션
- 다양한 양자화 방식 지원

**단점:**
- VRAM을 많이 사용 (90% 사전 할당)
- CPU 전용 실행 불가
- 모델 전환 시 서버 재시작 필요
- 셋업이 상대적으로 복잡

#### llama.cpp 기반 (Ollama, LM Studio)

**장점:**
- CPU만으로도 실행 가능
- 매우 빠른 시작 시간 (메모리 맵핑)
- 낮은 메모리 사용량
- 쉬운 설치 및 사용
- 다양한 하드웨어 지원 (심지어 모바일)
- 빠른 모델 전환

**단점:**
- Multi-GPU 지원 제한적
- 동시 다중 요청 시 처리량 낮음
- 엔터프라이즈 기능 부족
- GGUF 포맷 변환 필요

## 9. 빠른 시작 가이드

### 9.1 vLLM 설치 및 실행

```bash
# 설치
pip install vllm

# Python API 사용
python -c "
from vllm import LLM, SamplingParams

llm = LLM(model='meta-llama/Llama-2-7b-hf')
sampling_params = SamplingParams(temperature=0.8, top_p=0.95)

prompts = ['Hello, my name is']
outputs = llm.generate(prompts, sampling_params)

for output in outputs:
    print(output.outputs[0].text)
"

# OpenAI 호환 서버 실행
python -m vllm.entrypoints.openai.api_server \
    --model meta-llama/Llama-2-7b-hf

# 또는 CLI 사용
vllm serve meta-llama/Llama-2-7b-hf
```

### 9.2 Ollama (비교용)

```bash
# 설치 (macOS/Linux)
curl -fsSL https://ollama.ai/install.sh | sh

# 모델 실행
ollama run llama2

# 서버 모드
ollama serve
```

### 9.3 vLLM API 호출 예시

```python
import openai

# vLLM 서버에 연결
client = openai.OpenAI(
    base_url="http://localhost:8000/v1",
    api_key="dummy"  # vLLM은 인증 불필요
)

# Chat Completion
response = client.chat.completions.create(
    model="meta-llama/Llama-2-7b-hf",
    messages=[
        {"role": "user", "content": "안녕하세요!"}
    ],
    temperature=0.7,
    max_tokens=100
)

print(response.choices[0].message.content)
```
